### 1. What it is, architecture, backend, how images cross Go/JS

**Purpose.** goja-cv is "a lazy, measurable image API in JavaScript, built for agents that have an eval tool" (README.md:3) [doc].
- An agent sends the body of an async function.
- Go builds and evaluates a lazy op graph.
- The agent gets YAML text plus up to 4 images ("looks").

**Its home domain is film-scan dust detection, which is relevant to chromobench** [code]:
- gold tests on human-labelled "DUST-002" scan tiles (`pkg/cv/ops/peaks_gold_test.go:15-26`, `realdata_test.go:21-38`);
- a VueScan LinearRaw DNG test (`realdata_test.go:145`);
- the model library `pkg/cvsession/testdata/scripts/dust/helpers.js`.

**Layers, bottom to top** [code]:
- `pkg/cv/buffer` and `parallel`: buffers, IO, pyramid, band-parallel loops.
- `kernels`: pixel kernels.
- `graph`: registry, hash-consed builder, evaluator, cache, workspace, errors.
- `ops`: every op as an `OpDef`.
- `look`, `dataout`, `docs`: looks, saved files, agent guides.
- `pkg/gojamod/cv`: the go-go-goja module. `binding.go` plus the embedded `prelude.js`.
- `pkg/cvsession`: the replapi eval session, result processor and MCP server.
- `cmd/goja-cv`: the CLI.
- `pkg/xgoja/providers/cv`: the xgoja provider.

`examples/` contains only `examples/xgoja/cv-agent/xgoja.yaml`. `testdata/` holds two gradients; the planted scan is generated by `internal/testimage`.

**Backend: pure Go. There is no gocv/OpenCV and no C in the image path** [code].
- Grep finds nothing for OpenCV. `x/image` is used only for LZW.
- Images are planar float32 in linear light: `Buffer{W,H,C; Pix []float32; Scale}` with C = 1 or 3 (`pkg/cv/buffer/buffer.go:7-14`).
- Kernels never mutate inputs, because buffers are shared through the cache.
- Encodings are `srgb`/`linear`; working spaces are `linear`/`encoded` (`encoding.go:10-120`). Luminance uses Rec.709 on linear light.
- A preview pyramid serves looks from the coarsest adequate level (`pyramid.go:11-80`).
- Decoders are their own, pure-Go code, including the TIFF/DNG parser. They read PNG, JPEG, TIFF 8/16/float, LinearRaw DNG and `.npy` (`decode.go:89`).
- **CFA raw is refused.** There is no ICC, no camera matrix and no demosaic (`decoders_test.go:234-240`).

**Go/JS boundary: pixels never enter JavaScript** [code].
- JS holds Proxies over `{__id, __kind}`. Their methods are generated from the Go registry (`prelude.js:3-35, 217-224`).
- `await` on a Value or Regions node evaluates at scale 1 on another goroutine and settles the promise by posting back to the owner goroutine (`binding.go:247-288`).
- `await` on an Image returns a static summary and computes nothing (`binding.go:251-253`).
- Regions arrive as plain arrays. Each item carries a hidden `[node, index]` link (Symbol key), so filtered items passed back still mean their exact pixels (`prelude.js:44-77`).
- Looks are Go `resultcontent.Provider`s, rendered lazily as JPEG/PNG (`look/look.go:1-12`).

### 2. JS API surface

**Eval contract** [code]:
- Code is wrapped as `__cv_run(async function(){…})`, so line numbers map back to the agent's code (`cvsession/session.go:298-306`).
- Globals are `cv` (with a did-you-mean Proxy), `mem` (persists across evals; `const`/`let` do not), and `img` plus named images via `cv.open(p, {name})` (`cvsession/init.js`).
- `__cv_run` waits for every `cv.save` and `cv.load` the eval started (`init.js:64-108`).
- Small finding: the package comment at `session.go:2-3` still lists `P`, `show` and `doc` globals that no longer exist.

**The `cv` object** (`prelude.js:239-299`) [code]:
- `open`, `help` (never throws), `docs.list/search/read`, `explain` (evaluates nothing), `save`, `load`, `scripts`.
- Module ops `compare` and `sheet`.

**Ops come from one registry** (`graph/registry.go:313`) [code]. Each is an `OpDef`.
- `OpDef` (registry.go:235-299) carries:
  - `On`/`Returns` kinds: Image, Regions or Value. "Mask" means a 1-channel Image.
  - `Space` rule: Follows, Physical or Display.
  - `Class`: pixel, geometric or decoration, which controls zoom behaviour.
  - `Identity`, `AnalysisScale`, `Fields` (result schema), `Validate`, `Builders` (lambda args), `Expand` (macros), `Run`, `Doc`, `See`.
- **The option codec is `ArgSpec`** (registry.go:149-182). It carries:
  - type strings such as `enum:…`, `box`, `point`, `Mask` and `Regions|Mask`;
  - units: DocPx, DocPx², Fraction, Level;
  - hard `Min`/`Max` (`E_ARG_RANGE`);
  - a soft `Usual` range with hint (`RANGE` warning);
  - nested `Options`;
  - `Redirects` for names agents actually typed;
  - `Doc`.
- Dotted names become namespaces: `img.mask.luminance`, `detect.specks`.
- A representative op is `exposure`/`levels` in `ops/tone.go:17-82`.

**Lazy evaluation and caching** [code].
- Nodes are immutable and hash-consed: `sha256(op, canonical args, meta, input hashes)` (`graph/node.go:17-95`).
- The cache key is hash plus quantised scale. Concurrent identical work is deduplicated with singleflight. The LRU is byte-capped at 2 GiB (`eval.go:103-254`, `cache.go`, `engine.go:12-33`).
- Warnings are cached and replayed on a hit.
- Measured on 24 MP [run]:
  - a preview look took about 0.55 s for the whole process;
  - a full-resolution chain took 824 ms, then 178 ms when only the last op changed;
  - a cold full-frame `stats` took about 4.8 s;
  - RSS peaked at 1.6 GB.

**Space on the image.** `img.as("linear")` is the one conversion. Physical ops compute in linear light and return in the caller's space.
- `cv.explain` showed the builder-inserted `as(to:"encoded")` around `exposure` [run].
- This reverses GCV-001's per-op space [doc].

**Builder lambdas and masks.** `img.within(mask, i => i.exposure(-0.6))` runs the lambda once at build time with a placeholder (`ops/composite.go:15-35`) [code]. This is dodge/burn already.
- Mask ops: `luminance`, `color`, `box`, `ellipse`, `gradient`, `flood`; `and`, `or`, `minus`, `not`; `feather`, `refine`; `erode`, `dilate`; `components`, `coverage`.

**Looks** [code]:
- `node.look({zoom, ruler, …})` delivers at most 4 per eval and 8 MiB in total. Captions show the op chain and the scale.
- `cv.sheet(items, {views})` is a contact sheet whose caption lists cell ids (`ops/sheet.go:304`).
- `cv.compare` and `img.overlay` are decorations.

**Measurement** [code]:
- `peaks({radius:[2,4,8]})` returns sub-pixel local maxima of the core/ring step, with snr against each spot's own ring (`ops/peaks.go:64-86`).
- `measure(items)` returns step, spread, snr and stepChroma per item (`ops/regionmeasure.go:317-346`).
- Also `stats`, `histogram`, `profile`, `sample`.

**Saving and sandboxing** [code].
- `cv.save` picks the format from the extension. It refuses a second save to one path in an eval (`E_DUPLICATE`), never follows a symlink, never overwrites a file the session opened, and writes a temp file then renames it (`ops/funcs.go:65-74`).
- The workspace is Go `os.Root`: `--root` (given once) is read-write and `--read` is read-only (`graph/workspace.go:15-76`).
- Sessions load only `cv` and `timer`, and `require` refuses files (`session.go:162-191`). That hole was found by agents "within two runs" [doc].

**Task libraries** [code].
- `cv.load(path, args)` runs a file as `async function(args)`. `--prelude` loads files at session start.
- The "model library" is `testdata/scripts/dust/helpers.js`, which defines `mem.spots` and `mem.sheet`.
- The docs say this was built because 39 annotator agents each pasted a 3 KB helper file into evals [doc].

**Example snippets** (all executed by tests):
```js
const s = await img.stats()
const fixed = img.levels({ black: s.p01, white: s.p99 }).exposure(0.25)
cv.compare([img, fixed], { mode: "side" }).look("before / after")
const dust = (await img.detect.specks()).filter(r => r.score >= 0.5)
return { after: await img.heal(dust, { radius: 3 }).check.dust() }
```

### 3. Agent ergonomics, decisions and lessons

**What the agent is told** [code].
- MCP instructions are kept under 4000 chars (`cvsession/reference.go:11-48`). They cover the eval contract, "await gives data", "never read a coordinate off a picture", "apply the `fix:`", and about 20 core calls.
- A custom eval tool replaces replmcp's generic one.
- Resources: `cv://reference` (generated from the registry), `cv://docs/<id>`, `cv://guide/<slug>`. Prompt: `cv-agent` (`mcp.go:89-150`).
- Tool input schemas say when to omit optional fields, because "agents invent values for unexplained options" (`mcp.go:45-52`).

**What the agent gets back** [code].
- YAML capped at 9000 chars. An explicit message appears when nothing was returned.
- Compact tables: an array of ≥ 2 flat records becomes a header plus rows, with a budget of ⅔ of the cap (`tables.go:16-29`).
- Warnings carry line numbers.
- A context block lists images, `mem` keys, `mem` function signatures, and the **doc line of every new or changed function**. The doc line is read from `Function.prototype.toString`: it is the first comment of the body (`processor.go:470-540`, `gojamod/cv/describe.go`).

**Errors** are `{code, message, where (line), path, hint, fix (literal), valid}` (`graph/errors.go:15-50`) [code].
- The node Proxies turn common LLM mistakes into structured errors: number coercion of a lazy node, mutation, reading fields before `await` (`prelude.js:140-215`).
- [run] examples:
  - `E_UNKNOWN_OPTION "blak"` → `fix: levels({ black: 0.1 })`;
  - `E_NOT_AWAITED` → `fix: (await img.stats()).p01`;
  - `E_UNKNOWN_METHOD "exposre"`.

**Determinism.**
- Hash-consing plus canonical arguments, and `AnalysisScale` keeps region ids independent of preview size [code].
- A fixture differed between amd64 and arm64 in the 5th digit, and the column was dropped (commit `0e96cce`) [code].

**Evidence-driven process** [doc], which is the most reusable meta-pattern:
- **GCV-004** measured 18 small-model pi runs (751 evals).
  - Params/sliders were used **0** times, value lifting 4 times, `await` 1139 times against 85 for `cv.evaluate`, and only 14 of 246 synonyms were ever typed.
  - v2 therefore deleted params, lifting, the Mask kind, `.where/.sortBy` and `show`, for a net −2,950/+900 lines.
  - Its principles: literal options with `await` for data dependencies; space on the image; masks as images; regions as arrays; one save; one workspace.
  - Result: `E_ACCESS` errors went to 0 and calls fell. Recall did not change ("the agent's ranking was the limit, not the API").
- **GCV-005** came from 39 Sonnet annotator runs. It produced `cv.load`/`--prelude`, the context-block signatures, compact tables, sheet captions with ids, and `peaks`.
  - Its rule: "never make a model read a number off a picture; every look comes with the data it shows."
- **Workflow:**
  - Roles: a coordinator, one design writer, cold review-readers grading findings P1/P2/P3, and one implementer per ticket.
  - Numbered "deviations" are appended to each design doc: 50 in GCV-004 and 45 in GCV-005.
  - Built features were deleted when evidence said they were noise: the `UNUSED_NODE` lint (18 of 19 warnings false), `Halo`/`CROP_FIRST`, and `grow`/`shrink`.
- **A deviation that matters for chromobench:** a "ranking regression" was actually density tiles read as sRGB. Mis-declared scan encodings silently skew analysis.

### 4. Packaging and testing [code]

**CLI** (`cmd/goja-cv`) is Cobra with Glazed help pages. The commands are not Glazed commands.
- Commands: `run`, `eval -e`, `ops`, `help`, and `mcp` (stdio or `--http`; `--root` required).
- Flags: `--image`, `--root`, `--read`, `--prelude`, `--out`, `--json`, `--timeout-ms`.

**go-go-goja wiring:**
- `Module` implements `modules.NativeModule` and is registered in `init()` via `modules.Register` (`gojamod/cv/module.go:63-182`).
- `Registrar` implements `engine.RuntimeModuleRegistrar` and creates one engine per runtime.
- A thin `__`-prefixed native binding (`binding.go:40-63`) sits under an embedded `prelude.js` whose method tables come from the registry.
- The session (`session.go:162-293`) uses:
  - `engine.NewRuntimeFactoryBuilder` with a no-file `require` loader and `MiddlewareOnly("timer")`;
  - a `replapi.App` with a custom replsession `ResultProcessor`/`BeforeEvalHook`/`FailureProcessor` and `resultcontent` limits;
  - `replmcp.NewServer(... WithExtraTools)`.
- go-go-goja is pinned to a PR pseudo-version (go.mod:11).

**xgoja:** `pkg/xgoja/providers/cv/cv.go` registers package `goja-cv`, module `cv`, with a JSON-schema config. `examples/xgoja/cv-agent/xgoja.yaml` (`xgoja/v2`) builds `run`/`repl`/`mcp`, but without the cv result processor.

**Tests:**
- unit tests in every package;
- **golden looks**, compared exactly on 8-bit pixels before caption and JPEG (`look/golden_test.go:19-28`);
- a **planted-fault synthetic scan** with known specks (`internal/testimage/planted.go`);
- **env-gated gold tests** on real labelled tiles that compare two methods in one run rather than absolute counts;
- **every docs JS block runs** (`cvsession/docs_test.go:91-104`);
- **every documented CLI command parses** (`cmd/goja-cv/doc_commands_test.go:100`);
- a pinned representative agent result (`tables_test.go:79-92`);
- acceptance tests;
- `make smoke`.
- CI runs `-race`, lint, govulncheck, gosec and CodeQL.

### 5. What does not transfer to an interactive GUI with GPU or real-time previews

1. **Single owner goroutine per JS VM, evals serialized and bounded by a 60 s timeout.**
   - A goja quirk makes a session unusable after an interrupt in an async continuation (`processor.go:314-331`, `session.go:370-412`) [code].
   - The GUI must call the Go core directly, not go through JS. Document state must live in Go, not in `mem`.
2. **Live params were deleted** because agents didn't use them (GCV-004 D1) [doc+code]. Humans need exactly that: stable, named, mutable parameters.
3. **There is no persisted edit recipe, undo or history.** Graphs are per eval and only `mem` persists.
4. **CPU only, full frame, with no tiled or windowed evaluation.** `Halo` was designed and then deleted [doc]. No GPU or real-time work appears anywhere. At 24 MP that is about 0.5 s per preview and seconds for full-frame stats [run], fine for agents and far from 60 fps.
5. **Looks are not a display pipeline.** They are JPEG/PNG files, at most 4 per eval and 1568 px, with burned-in captions. There is no colour-managed display output, progressive refinement, or "latest request wins" scheduling.
6. **Memory:** float32 planar data costs 12 B per pixel per intermediate, against a 2 GiB cache. That is about 1.2 GB per intermediate at 100 MP.
7. **No colour science:** no ICC, camera matrices, demosaic, densities, or spectral data. This is chromobench's core, so it is all new work.
8. **Agent-only output shaping** (YAML caps, tables, context block, `E_NOT_AWAITED` proxies) and the `--root`/`--read` path sandbox belong in an agent façade. Give the agent a catalog API instead of paths.

**What does transfer:**
- the op registry as one schema that generates the JS API, help, *and* GUI controls (from `Min`/`Max`/`Usual`, enums and units);
- hash-consed nodes plus a cache keyed by (hash, scale) plus the pyramid;
- doc-px coordinates with `AnalysisScale`;
- the three op classes;
- masks as images plus `within`;
- spaces on the image with builder-inserted conversions, extended to camera RGB, XYZ, log-exposure and density;
- structured errors with literal fixes;
- tests that run the docs, golden and planted fixtures, and env-gated gold tests;
- the evidence-driven delete-what-agents-don't-use process.
